# Development workflow

RetailOps AI uses Python 3.12 and `uv` for dependency and environment management.

Repository automation is implemented in Python. Bash wrappers are intentionally not used, so the same commands work from Git Bash, PowerShell, Command Prompt, and Unix-like shells as long as Python and `uv` are available.

## First-time setup

From the repository root:

```bash
python scripts/bootstrap.py
```

The bootstrap script:

1. checks that `uv` is available;
2. resolves the Python 3.12 environment;
3. installs the project dependencies;
4. generates or updates `uv.lock` when dependency resolution succeeds;
5. runs the validation checks.

## Validation

Run the project checks with:

```bash
python scripts/check.py
```

The current checks are:

```text
Python version
Ruff static checks
pytest test suite
```

## Python orchestration scripts

Cloud and data workflows use Python entry points under `scripts/`:

```text
bootstrap.py
check.py
download_m5.py
validate_m5.py
profile_m5.py
upload_m5_to_gcs.py
load_m5_to_bigquery.py
run_dbt_staging.py
run_dbt_silver.py
run_dbt_gold.py
run_dbt_ml_contract.py
run_dbt_baselines.py
run_dbt_features.py
train_lightgbm_runner.py
```

The scripts share environment loading, subprocess execution, and dbt helpers through `scripts/_common.py`.

## Lockfile policy

`uv.lock` must be generated by `uv`; it must never be written or edited manually.

Whenever dependencies change, run:

```bash
uv sync
python scripts/check.py
```

Commit the resulting `pyproject.toml` and `uv.lock` changes together after validation.

## Secrets

Use `.env` for local values only. The repository tracks `.env.example`, but never real credentials, service-account keys, or local data extracts.
